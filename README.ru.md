# Click-Trained Re-ranker поверх Vector Search

[English](README.md) | **Русский**

Прототип: обычный векторный поиск (ANN по косинусному сходству) плюс лёгкий слой learning-to-rank (LightGBM lambdarank), который дообучается на накопленных кликах и переранжирует выдачу.

## Идея

Типичный векторный поиск статичен: он отдаёт top-K по косинусному сходству, и это сходство никак не учится на поведении пользователей. Здесь поверх него логируются клики, и на них обучается лёгкая модель, которая переупорядочивает кандидатов из ANN. Сам ANN не заменяется.

Модель смотрит не на эмбеддинги, а на признаки пары «запрос — документ»: косинусное сходство, BM25, исходную позицию в выдаче, длину документа и совпадение темы. Поэтому видно, почему документ поднялся или опустился.

Реальных кликов нет, так что и корпус, и поведение пользователей синтетические. В эмбеддинги документов специально добавлен шум, чтобы исходная выдача была неидеальной и переранжированию было что исправлять.

## Структура

```
backend/
  requirements.txt
  app/
    main.py        FastAPI: /generate, /simulate-clicks, /search, /click,
                   /train-reranker, /eval, /queries, /status
    config.py      константы (шум эмбеддингов, K, сиды)
    data_gen.py    синтетический корпус: 288 документов (8 тем × 4 подтемы),
                   40 запросов, скрытая релевантность 0-3
    embedder.py    sentence-transformers (all-MiniLM-L6-v2)
    ann.py         шум в эмбеддингах + numpy-ANN (cosine top-K)
    features.py    признаки пары (запрос, документ): cosine, bm25,
                   original_rank, doc_length, topic_match
    ranker.py      LGBMRanker (lambdarank), фолбэк — логистическая регрессия
    simulate.py    симуляция кликов: P(клик | релевантность) / sqrt(позиция)
    eval_ndcg.py   NDCG@10 baseline vs reranked на отложенных запросах
    state.py       оркестрация, артефакты в backend/data/
    db.py          SQLite: documents, queries, relevance, clicks
frontend/          Vite + React: один экран, две колонки side-by-side
```

## Запуск

### Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

Первый вызов `POST /generate` скачает модель эмбеддингов (~90 МБ) — это одноразово.

### Frontend

```bash
cd frontend
npm install
npm run dev                     # http://localhost:5173
```

## Сценарий демо

1. **1 · Generate dataset** — корпус, запросы, зашумлённые эмбеддинги, ANN-индекс.
2. Выбрать запрос → **Search** — видны обе колонки с признаками каждого документа.
3. **2 · Simulate clicks** — клики по обучающим запросам с учётом позиции в выдаче; ANN специально неидеален (шум занижает часть релевантных документов).
4. **3 · Train re-ranker** — LGBMRanker учится на накопленных кликах.
5. Снова **Search** — порядок во второй колонке изменился, признаки объясняют почему.
6. **Evaluate NDCG** — NDCG@10 на отложенных запросах: baseline vs reranked.

Ручные клики по карточкам пишутся в ту же таблицу `clicks` — после них можно переобучить модель и увидеть, как изменился порядок.

## Замечания

- Артефакты лежат в `backend/data/`: `app.db`, `doc_embeddings.npy`, `query_embeddings.npy`, `reranker.pkl`. `POST /generate` пересоздаёт всё, включая клики.
- Корпус и шум зафиксированы сидом (`SEED=42`), симуляция кликов тоже (`SIMULATION_SEED`). Каждое нажатие **Simulate clicks** очищает таблицу кликов — **вместе с ручными** — и заполняет её заново тремя проходами симуляции, так что результат воспроизводим.
- Отложенные запросы (~25%) помечены `is_eval`: симуляция по ним не кликает, качество оценивается только по ним.
- Переранжирование берёт 50 кандидатов из ANN и возвращает лучшие 10, поэтому может «вытащить» документы, которые шум выбил из первой десятки.
- Рангер переходит на логистическую регрессию, если `lightgbm` не установлен или если клики есть меньше чем по 5 запросам (на 1–2 группах LightGBM не обучится). Тип модели виден в статусе.
- Ручной клик принимается только для документов из первой десятки ANN и записывается с позицией в исходной ANN-выдаче, а не в переранжированной колонке.
